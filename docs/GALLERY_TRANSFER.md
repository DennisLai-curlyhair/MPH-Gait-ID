# Gallery Export and Import

Gallery transfer moves registered identity descriptors between installations.
It does not train a model, record point clouds, or convert descriptors between
models. This is a conference-application enhancement, independent of journal
model research.

## Desktop Workflow

1. Stop offline jobs, live identification/enrollment, and performance benchmarks.
2. On computer A, open **Gallery Manager > Export all Gallery** and choose a
   `.mphgallery` file. Export includes all models and identities, regardless of
   the current Gallery filters, including inactive records.
3. Transfer the archive through a trusted, protected channel. On computer B,
   install the application and the same model bundles/weights separately.
4. Open **Gallery Manager > Import Gallery**. Review the **People** and **Models**
   tabs before accepting the import.
5. New identities are selected by default. An existing local ID is a conflict
   even when the name is identical. Conflicts default to **Skip**; use **New ID**
   or **Merge into...** to explicitly associate the same person. Merging keeps
   the local name, note, and status. Previously imported identities retain their
   established association.
6. Choose **Import**. The result displays inserted, duplicate, and skipped
   embedding counts, the pre-import backup, and the retained archive paths.
7. Select the matching model and T in the normal Gallery/recognition pages.
   Re-run a known probe before deployment on the new computer.

The dialog runs transfer work in a background thread. Close is blocked during
an active transfer. Files are not imported merely by selecting them for preview.
Preview initializes transfer bookkeeping if needed but does not change people,
models, or Gallery embeddings.

## Compatibility

Import requires matching verified checkpoint SHA256, architecture/model settings,
input representation, point count, coordinate adapter, normalization, runtime T,
drop-first setting, and preprocessing profile. The encoding source files are also
fingerprinted. Folder paths and bundle display names are not compatibility keys;
an identically configured bundle with a different ID can be mapped locally.
Source fingerprints normalize Python line endings and path separators so a normal
Windows checkout and Linux checkout can match.

The target runtime records are generated by the same helper as ordinary
registration. Existing model keys and the Gallery schema version remain unchanged;
transfer bookkeeping uses additional namespaced tables. No checkpoint is loaded
or executed during transfer; installed checkpoint files are hashed only.
The preprocessing check uses the recorded profile identifier. It cannot certify
historical detector/filter settings or camera calibration within that profile;
verify those separately on the destination device.

Older enrollment records do not contain a complete enrollment-time encoding
contract. For these records, export attaches the current local bundle and source
specification. Confirm that these settings still describe the original enrollment.
An export cannot retrospectively prove that a bundle was never edited. Imported
specifications are preserved for later re-export. Missing specifications or
mismatching versions are not automatically treated as compatible.

Unavailable models are skipped, not mixed into the active model Gallery. The
validated archive is retained locally. Install the matching bundle and import
that retained archive again to add the remaining embeddings. Previously imported
rows are deduplicated. An updated checkpoint or encoder needs re-enrollment;
Stage A cannot reconstruct point clouds from embeddings.
Opt-in [Stage B foreground recordings](ENROLLMENT_SOURCES.md) are stored
separately and are not included in Gallery transfer archives or SQLite-only
backups. Use [Stage D source transfer](SOURCE_TRANSFER.md) for foreground
recordings and [Stage C registration](SOURCE_REGISTRATION.md) for cross-model
re-encoding. Source archives and Gallery archives can be imported in either order.

## Integrity and Recovery

The data-only ZIP container has exactly three members:

```text
manifest.json   format/version, timestamp, payload SHA256 values
records.json    identities, model specifications, source/pass/window metadata
embeddings.bin concatenated little-endian FP32 normalized descriptors
```

No ZIP members are extracted as paths. The importer checks member names, versions,
sizes, checksums, record references, descriptor dimensions, finite values, and
L2 norms. It does not deserialize pickle, PyTorch, or object-array payloads.
The current limits are 512 MiB compressed/uncompressed, 16 MiB per JSON member,
and 100,000 records per collection.

Export reads one SQLite transaction snapshot. Import first retains the validated
archive and makes a consistent SQLite backup, then uses one database transaction
for the merge. If the archive, target Gallery, or model availability changes after
preview, repeat the preview. Validation/merge errors roll back Gallery writes;
the retained package and backup may remain. Existing inactive embeddings are not
reactivated by repeated import. Deleted imported rows are not silently restored.

Permanent deletions made through [Gallery Manager](GALLERY_MANAGEMENT.md) are
tracked locally. Deleted people and embeddings are skipped by default. Enable
**Restore previously deleted records** to explicitly recover selected archived
records, with an additional confirmation and restored counts in the result.
A deleted person requires an unused target ID; use **New ID** if the old ID is
occupied. Existing inactive entries stay inactive. See the
[restoration workflow](GALLERY_MANAGEMENT.md#restore-deleted-records) for scope
and audit details. Reused Person IDs receive new portable identities.
These safeguards do not delete data on other computers
or revoke archives. Raw SQLite deletion is unsupported and may require repair
before an archive can be imported again.

Export also persists portable identity mappings. Management and transfer share
the same local deletion history; the archive format remains version 1.

Storage is relative to the configured database, not the source computer:

```text
data/
  gallery.sqlite3
  gallery_transfer/
    incoming/<archive-sha256>.mphgallery
    backups/gallery-<unique-id>.sqlite3
```

To restore a backup, fully close the application and every other connection to
the database. Keep the current database and any sidecar files together as a
separate recovery copy, then restore the backup to the configured database path.
Do not copy a backup over an actively used database. No automatic destructive
restore is performed by the application.

## Privacy and Scope

- Archives, retained packages, and backups contain personal biometric data and
  are **not encrypted**. Protect them using device access controls and an encrypted
  transfer/storage channel. SHA256 detects corruption, not sender authenticity.
- Weights, original point clouds, RGB/depth, credentials, local source paths,
  sensor serials, and recognition thresholds are not included. Names and notes
  are included; review any sensitive information entered in those fields.
- Only necessary window/pass metadata is exported. Detailed source/session JSON
  files and their local paths are deliberately omitted. Imported source IDs are
  portable identifiers; they do not point to a playable recording.
- `.mphgallery`, generated backups, and `gallery_transfer/` are ignored by Git.
  Git ignore rules are not access controls and do not remove previously tracked
  copies. The operator remains responsible for retention and secure deletion.
- Repeated import is a merge, not bidirectional synchronization. Later source-PC
  renames, deactivations, or deletions do not overwrite the target PC's state.
- The same weights do not guarantee identical numerical results on different
  hardware/software, or equivalent accuracy with a different camera/site.
  Recheck reference probes and calibrate rejection thresholds independently.

## Command Line

Run from the repository root in the installed application environment:

```bash
python -m mph_gait_id.gallery_transfer_cli export gallery.mphgallery
python -m mph_gait_id.gallery_transfer_cli preview gallery.mphgallery > data/import_preview.json
python -m mph_gait_id.gallery_transfer_cli import gallery.mphgallery --preview-file data/import_preview.json --apply
```

For an isolated database, put `--database /path/to/gallery.sqlite3` before the
subcommand. The `import` command requires a saved preview and `--apply`.
Conflicting IDs default to skip. An optional `--person-map data/person_map.json`
maps every preview person `uid` to a destination ID, or `null` to skip. Mapping
to an existing ID is an explicit merge; confirm the real person's identity first.

For explicit restoration, generate a fresh preview and add `--restore-deleted`:

```bash
python -m mph_gait_id.gallery_transfer_cli import gallery.mphgallery --preview-file data/import_preview.json --restore-deleted --apply
```

The flag restores compatible deleted features for selected people. Deleted people
with unused IDs are selected automatically; occupied IDs remain skipped unless
`--person-map` assigns an unused, distinct ID. Deleted people cannot be merged into
existing people. Without the flag, deletion protection stays enabled. Review the
preview's `restorable_embeddings` counts and `target_exists` fields before
confirmation. Missing models remain skipped; regenerate previews after updating
the application, Gallery, or model bundles.

## Verification

```bash
python -m unittest discover -s mph_gait_id/tests -v
python -m unittest discover -s scripts/tests -v
```

Tests use synthetic embeddings and temporary databases: round-trip equality,
duplicate/inactive handling, missing models, identity conflicts, compatibility,
checksum/format defenses, stale previews, and transaction rollback. These do not
constitute physical Azure Kinect or cross-machine live accuracy validation.
